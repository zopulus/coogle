# 设置保存、重启与状态重试

日期：2026-11-08。基线：Coogle 1.3.8 / 138，`54329ad`。

## 问题与修改

普通设置与 Root 操作分别使用串行队列。原实现允许重启作用域早于普通设置提交完成，SystemUI 重新启动时可能仍读取旧开关。现在在请求重启时取得普通设置队列的完成点，Root 队列执行重启前等待此前的设置任务完成。保留两条队列，使 Root 授权等待期间仍可保存普通设置；等待在后台执行，不占用主线程。

保存中的 key 使用一份进程内可观察状态，与队列一起跨 Activity 重建。对应条目显示“正在保存…”并暂时禁用，重启按钮及确认按钮等待保存完成。保存结束时先移除 key，再判断原 Activity 是否销毁，避免新页面永久停留在保存中。重启执行期间暂停当前页面的新开关操作。

附属模块检测曾把自动检查与手动检查都限制为每次前台一次，检测失败后再次点击状态卡不会重试。现在只在自动入口检查限次标记；手动入口仍保留安装中、检查中和作用域请求中的互斥条件，成功后再清除此前的检测错误。没有增加轮询或常驻服务。

## 验证

新增 `SettingsActivityTest` 直接调用编译后的生产 Activity，通过独立测试边界控制偏好提交、UI 回调和 Root 命令。测试与 Hook 边界桩分开加载，不修改生产业务逻辑。

- 修改前，手动重试、保存期间重启、界面重建后重启三项均按预期失败。
- 修改后覆盖自动检查去重、手动失败重试及成功清错、两种重启顺序、界面重建后的同 key 去重与成功/失败清理、活跃页面保存失败提示及重试、Root 等待不阻塞普通设置。
- 故意将保存标记清理移回 Activity 销毁检查之后，测试失败；随后按原字节恢复源码。
- 新测试已加入 `testHookLifecycle`，标准 `build.ps1` 会执行它。
